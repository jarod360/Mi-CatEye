# Mi-CatEye

Home Assistant 猫眼接入集成 · **测试版 0.2.0b5**

面向已验证的 `loock.cateye.v02`：一条上游实时会话供电视、小爱屏幕和手机共享，同时提供门铃、经过、停留事件，以及云端事件录像回看。当前为个人非商业 Home Assistant 使用的候选版本，不是官方集成，不承诺兼容所有设备。

## 功能与范围

- 门铃、经过、停留事件，电量和在线状态。门铃提示状态在最后一次按铃 60 秒后复位。
- H.265 实时视频：按需取流，三端共享；没有全天预加载。
- 电视 EXO 弹窗；小爱全屏、来访语音和音量恢复；手机通知点击打开实时视频。
- 手机前台可选 Browser Mod 定向弹窗，需在选项填写该手机的 Browser Mod ID；后台仍依赖 HA Companion 通知。不会向所有浏览器广播，也不会强行从后台拉起 App。
- 云端事件录像：日期、起止时间、经过/停留/门铃筛选，上一段/下一段、播放和下载。保留期以云端实际提供为准，只有事件片段，不是连续录像时间轴。
- 内置受集成管理的精简 go2rtc 媒体核心，通常无需另装 go2rtc 加载项或 Xiaomi Home 集成来服务同一台猫眼。
- 小爱和 TV 视频弹窗内直接接通/挂断、选择成熟男声短句回复；小爱仅需一个定制接收器。通话复用正在观看的视频连接，不另拨猫眼。TV 支持方向键、确认键；选好短句后焦点直达“发送”。
- 手机/HA 视频页面可发送三条固定男声回复。手动查看入口可提示低电量；低电量不拦截按铃视频。

- 多摄像机接入（实验）：在集成选项中选择同账号下的摄像机，一套媒体核心按需管理各设备的独立视频流；每台设备的观看端共享该设备的上游。已实测 `chuangmi.camera.ipc009`、`chuangmi.camera.ipc021` 的 H.265 实时视频，不代表全部米家摄像机均可用。隐私遮蔽需由用户手动解除。
- 账号分组名称可在选项中自定义，默认只显示账号尾号；具体设备保留各自名称。
- 云录像查询使用主题色弹窗风格、24 小时时间与统一中文事件名称，包括“有人经过并按门铃”。

两款已验证摄像机 `chuangmi.camera.ipc021`、`chuangmi.camera.ipc009` 支持存储卡录像：按设备与日期查询、播放、下载和前后片段切换。回看与实时视频共用设备互斥控制，回看前先停止该摄像机的实时画面；文件按需取出，临时缓存最多 10 分钟、3 个文件、32MB。

**尚未支持**：猫眼存储卡回看、云台控制、额外摄像机对讲、浏览器实时麦克风通话。猫眼在米家确有存储卡回看入口，当前只是本项目尚未打通，不能理解为设备不支持。初次添加仍以受支持猫眼为入口；摄像机独立开户流程未完成。商品型号以米家返回的 model 为准。

## 安装

已验证环境：Home Assistant Core 2026.11.0，Linux amd64；安装包亦含 arm64 媒体核心，但 arm64 尚未实机验证。需要 HA 自带 FFmpeg，云端访问正常，以及账号能够访问目标猫眼。

1. 备份 HA。从[当前测试版源码 ZIP](https://github.com/jarod360/Mi-CatEye/archive/refs/heads/main.zip)（已含媒体核心），解压后将其中的 `custom_components/mi_cateye` 文件夹复制到 HA 的 `/config/custom_components/mi_cateye`，确认里面存在 `manifest.json`。不要覆盖整个 `custom_components` 目录。
2. 重启 HA，在「设置 → 设备与服务 → 添加集成」搜索 **Mi-CatEye**。
3. 按向导完成账号视频鉴权及事件 OAuth 授权；验证码和短信验证码只填在 HA 配置页。事件 OAuth 回调使用上游注册的 `http://homeassistant.local:8123`，授权浏览器需能访问此地址。
4. 配置电视和小爱接收器的局域网地址、手机通知服务；不用的端可以留空。
5. 从旧链路迁移时，先停止旧猫眼视频桥接和按铃自动化，再启用新视频和通知，避免两条物理猫眼会话。确认新链路正常后再清理旧组件；不要删除其他设备依赖的集成。

HACS 元数据已包含，但候选版本尚未完成独立 HACS 安装验收，优先按以上方式安装。

## 使用

- 实时画面：`/mi-cateye`；多摄像机在选项中勾选设备后，可使用各自摄像机实体。额外摄像机不会自动加入门铃通知。
- 录像回看：`/mi-cateye-recordings`，可选择猫眼云端事件或已配置摄像机的存储卡。
- 手机：选择 HA Companion 的 `mobile_app_*` 通知服务。前台自动弹窗另外安装并注册 Browser Mod，填写手机自己的 Browser ID。App 后台时能否接收通知取决于手机系统和 Companion 连接设置。
- 电视/小爱：需要兼容的局域网接收器，见 [接收器说明](docs/receivers.md)。单装 HA 集成不会自动给屏幕安装接收器。
- 主页面可放导航按钮，见 [卡片示例](docs/cards.yaml)。实体 ID 由 HA 根据设备名称生成，请选择你自己的实体。

## 实测状态与已知问题

- 授权、三类事件、三端分发、手机通知点击播放和云端录像播放/下载已在单台设备验证。
- 录像测试包含约 9、10、43 秒片段、三天日期查询、时间和事件类型筛选及前后片段切换。
- 电视曾出现偶发卡顿；首帧出现不代表持续流畅，尚未解决所有冷启动和缓冲问题。
- 最近一次卸载旧链路后的测试：电视首帧约 3.64 秒，小爱约 8.53 秒；用户报告小爱短暂黑屏卡顿。不能据此认定为开机原因。
- 手机前台弹窗在 rc1 补回，门铃图标定时复位已修复；47 项 HA 测试通过，用户实际按铃确认前台自动弹窗和约 60 秒图标复位正常。
- rc1 后续按铃采样：电视首帧约 4.96 秒，小爱约 4.56 秒；均未报告播放器错误、测试结束弹窗为零，小爱音量恢复。只代表本次测试，不等于长期稳定。请勿将候选版视为稳定版。
- 0.2.0b2：64 项 HA 测试及录像事件中文标签测试通过。两款额外摄像机已解码验证变化画面，并验证同设备多观看端共享上游；无严格长期稳定性结论。
- XiaoNexus 门铃保护接口兼容现有小爱接收器；不替换其认证或 AI 策略。两轮手动三端链路中的电视/小爱首帧约 4.8–5.2 秒，不是物理按铃到首帧的完整计时，也不能证明之前偶发问题的原因。
- 尚无严格的新旧总内存对照，不能承诺具体节省比例。
- 0.2.0b4：小爱双向通话、短句回复、退出返回已由用户确认；TV 通话接通、回复，以及 rc3 通话压低节目音量/挂断恢复已由用户确认，双向清晰度与回声尚待白天验证。
- 0.2.0b5：两款摄像机存储卡录像均完成真实完整文件下载与 HA 浏览器解码；三路实时视频及猫眼对讲无声启停回归通过。主题安防宽卡已有独立候选，等待猫眼回看完成后再部署，详见 [录像交接](docs/SD_PLAYBACK_HANDOFF_2026_11_06.md)。
- 当前仍未完成“物理按铃到首帧两秒内”目标；完整状态、协议细节和后续任务见 [通话交接](docs/TALK_HANDOFF_2026_11_05.md)。

## 隐私与网络

管理 API 和 RTSP 仅监听 loopback；播放由 HA 登录或短期路径签名保护。录像云端签名 URL 不返回前端。临时媒体和授权保存在 HA 本机，不应提交仓库；缓存仅按需建立，并在启动或再次使用时清理过期片段。不要公开配置目录、令牌、二维码、带签名的媒体链接或门口录像。

无需为媒体核心额外做公网端口映射。接收器只应允许 HA 主机访问。此项目不要求开放免认证 ADB、无障碍或设备管理权限。
