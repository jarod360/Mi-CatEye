# Mi-CatEye

Home Assistant 猫眼接入集成 · **候选发布版 0.1.0rc1**

面向已验证的 `loock.cateye.v02`：一条上游实时会话供电视、小爱屏幕和手机共享，同时提供门铃、经过、停留事件，以及云端事件录像回看。当前为个人非商业 Home Assistant 使用的候选版本，不是官方集成，不承诺兼容所有设备。

## 功能与范围

- 门铃、经过、停留事件，电量和在线状态。门铃提示状态在最后一次按铃 60 秒后复位。
- H.265 实时视频：按需取流，三端共享；没有全天预加载。
- 电视 EXO 弹窗；小爱全屏、来访语音和音量恢复；手机通知点击打开实时视频。
- 手机前台可选 Browser Mod 定向弹窗，需在选项填写该手机的 Browser Mod ID；后台仍依赖 HA Companion 通知。不会向所有浏览器广播，也不会强行从后台拉起 App。
- 云端事件录像：日期、起止时间、经过/停留/门铃筛选，上一段/下一段、播放和下载。保留期以云端实际提供为准，只有事件片段，不是连续录像时间轴。
- 内置受集成管理的精简 go2rtc 媒体核心，通常无需另装 go2rtc 加载项或 Xiaomi Home 集成来服务同一台猫眼。

**尚未支持**：SD 卡远程回看、通用多摄像头、云台控制、语音对讲。MJSXJ06CM/MJSXJ05CM 尚未实机接入本集成。

## 安装

已验证环境：Home Assistant Core 2026.10.4，Linux amd64；安装包亦含 arm64 媒体核心，但 arm64 尚未实机验证。需要 HA 自带 FFmpeg，云端访问正常，以及账号能够访问目标猫眼。

1. 备份 HA。下载候选版本安装包，解压到 HA 配置目录，使文件位于 `custom_components/mi_cateye/manifest.json`。不要覆盖整个 `custom_components` 目录。
2. 重启 HA，在「设置 → 设备与服务 → 添加集成」搜索 **Mi-CatEye**。
3. 按向导完成账号视频鉴权及事件 OAuth 授权；验证码和短信验证码只填在 HA 配置页。事件 OAuth 回调使用上游注册的 `http://homeassistant.local:8123`，授权浏览器需能访问此地址。
4. 配置电视和小爱接收器的局域网地址、手机通知服务；不用的端可以留空。
5. 从旧链路迁移时，先停止旧猫眼视频桥接和按铃自动化，再启用新视频和通知，避免两条物理猫眼会话。确认新链路正常后再清理旧组件；不要删除其他设备依赖的集成。

HACS 元数据已包含，但候选版本尚未完成独立 HACS 安装验收，优先按以上方式安装。

## 使用

- 实时画面：`/mi-cateye`
- 云端录像：`/mi-cateye-recordings`
- 手机：选择 HA Companion 的 `mobile_app_*` 通知服务。前台自动弹窗另外安装并注册 Browser Mod，填写手机自己的 Browser ID。App 后台时能否接收通知取决于手机系统和 Companion 连接设置。
- 电视/小爱：需要兼容的局域网接收器，见 [接收器说明](docs/receivers.md)。单装 HA 集成不会自动给屏幕安装接收器。
- 主页面可放导航按钮，见 [卡片示例](docs/cards.yaml)。实体 ID 由 HA 根据设备名称生成，请选择你自己的实体。

## 实测状态与已知问题

- 授权、三类事件、三端分发、手机通知点击播放和云端录像播放/下载已在单台设备验证。
- 录像测试包含约 9、10、43 秒片段、三天日期查询、时间和事件类型筛选及前后片段切换。
- 电视曾出现偶发卡顿；首帧出现不代表持续流畅，尚未解决所有冷启动和缓冲问题。
- 最近一次卸载旧链路后的测试：电视首帧约 3.64 秒，小爱约 8.53 秒；用户报告小爱短暂黑屏卡顿。不能据此认定为开机原因。
- 手机前台弹窗在 rc1 补回，单元测试通过，真实前台按铃及图标复位复测仍待完成。请勿将候选版视为稳定版。
- 尚无严格的新旧总内存对照，不能承诺具体节省比例。

## 隐私与网络

管理 API 和 RTSP 仅监听 loopback；播放由 HA 登录或短期路径签名保护。录像云端签名 URL 不返回前端。临时媒体和授权保存在 HA 本机，不应提交仓库；缓存仅按需建立，并在启动或再次使用时清理过期片段。不要公开配置目录、令牌、二维码、带签名的媒体链接或门口录像。

无需为媒体核心额外做公网端口映射。接收器只应允许 HA 主机访问。此项目不要求开放免认证 ADB、无障碍或设备管理权限。
