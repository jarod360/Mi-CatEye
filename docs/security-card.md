# 安防宽卡

实现：`frontend/mi-security-card.js`，需单独添加为 Lovelace module 资源；集成不会自动修改用户主题。已在旧主题与弧光主题的手机、桌面布局验证。

## 最终界面

- 两列宽卡，旧主题高 178px，弧光高 170px；默认封面不取快照、不预加载视频。
- 旧主题无标题图标，紫色餐桌椅及青绿色阳台平面图，各有淡紫/淡青圆角背景与轻描边、中间留缝；弧光恢复最初餐桌、窗景 SVG 简画和淡蓝绿底，标题使用 36px 底 / 25px CCTV 图标。
- 标题栏仅有图标式播放/停止按钮，没有门口录像入口。播放同时打开两路，点击单路放大，退出释放；放大保留同一个 iframe，并按实际视频比例计算弹窗尺寸。
- 封面右上角为小半球摄像机：云端报告在线时亮绿，离线灰；在线且隐私开启时为遮蔽标记。未知状态不视为离线，提示状态未知。
- 隐私开启时保留原封面，仅右上角摄像机标记增加图标内部的短斜杠，不覆盖封面或显示大幅隐私提示。点击播放先询问，确认后开启摄像并等待状态返回，再开始取流；取消不写入。未知状态不会自动开启摄像。
- 弹窗内“隐私模式/物理遮蔽”和“查看录像”均使用旧主题圆角浅灰按钮。隐私开关每次需确认；进入隐私会停止画面，退出隐私后恢复播放。
- 验证设备 `chuangmi.camera.ipc021` 有物理遮蔽，`chuangmi.camera.ipc009` 为软件隐私模式；仅对本次硬件行为负责，不推定其他固件相同。
- 录像入口先停止直播，仅显示当前设备和指定来源；不混入其他设备。未指定设备的猫眼录像入口仅提供猫眼云端和存储卡，不列出其他摄像机。

```yaml
type: custom:mi-security-card
variant: arc # classic 为旧主题
view_layout:
  grid-column: span 2
cameras:
  - device: "1" # 换成已配置摄像机 DID
    name: 餐厅
    scene: dining
  - device: "2"
    name: 阳台
    scene: balcony
```

## 状态与权限

状态取自原有视频账号的设备在线字段和 MIoT 摄像开关 2/1，不使用 camera.idle 或 HA availability 代替物理在线。页面可见时每 60 秒刷新，后台缓存 15 秒；这不是即时心跳。`mi_cateye/camera_state` WebSocket 仅接受本集成已选择的两款摄像机；写入必须附带明确确认，不接受任意属性或云端路径。媒体核心固定接口仅在 loopback，并列入既有访问白名单。原始账号、令牌、地址及云响应不返回前端。

验证涵盖取消唤醒零写入、未知设备拒绝、无确认拒绝、离线不拉流，以及真实阳台遮蔽、确认唤醒和实际视频解码。三路直播与猫眼通话无声启停回归通过；84 项 HA 测试、Go 单元测试及双架构安装预检通过。手机浏览器实时对讲和额外摄像机对讲仍在后续范围。

隐私控制延迟修复：后台仅发送一次设置指令，回执后最多执行 8 轮只读确认，总等待上限 35 秒；只有目标状态确认后才缓存成功。播放与隐私操作前绕过 15 秒状态缓存，避免刚在米家操作后依据旧值反向设置。忙碌期间禁用按钮并显示进度；失败记录型号、目标状态及耗时，不打印账号或原始云响应。当前日志不足以还原之前每次偶发失败，不能将此修复视为所有固件长期稳定性结论。

设备范围在页面复用和跳转时重新计算；旧设备的迟到结果不会覆盖新页面。未知设备不回退到其他摄像机。

放大直播时，两款已配置摄像机可用四向点动。每次点击只发一条局域网 miIO 指令，后台复核摄像机在线、隐私模式关闭且视频仍在播放。同一台设备的操作串行执行，发送间隔至少 0.4 秒，超时不会自动重发。界面显示的是指令发送状态。反向点动的回拨精度因设备而异，目前没有自动回原位。

阳台 ipc021 的直播会读取 CS2 控制消息，避免点动通知积满 0 号通道的 10 条队列后切断视频。修复后本机连续点动 20 次无断流，最长解码帧间隔约 0.22 秒。
