# Mi-CatEye 0.1.0a1 测试安装

这是内部测试版，支持 Linux amd64 和 arm64，首先验证 HA 2026.10.4 与 loock.cateye.v02。压缩包内含两个平台的精简媒体核心及校验清单，不需要另装新的 go2rtc 加载项。

## 安装

1. 保留现有 Xiaomi Home、doorbell_local、go2rtc 和门铃自动化，先备份 HA。不要同时建立另一条猫眼视频会话。
2. 将压缩包内 `custom_components/mi_cateye` 整个目录复制到 HA 的 `/config/custom_components/mi_cateye`，不是安装到电脑目录。其他目录不要覆盖。
3. 重启一次 HA，然后到「设置 → 设备与服务 → 添加集成」搜索 Mi-CatEye。若搜索不到，刷新浏览器并查看 HA 集成加载日志。
4. 填写米家账号、密码、地区和本机手机能够访问的 HA 根地址；密码只用于登录，不写入配置条目。若有验证码，按界面完成。
5. 选择猫眼，再完成事件 OAuth 授权。事件授权与视频登录是两个不同的鉴权范围，需使用拥有同一猫眼的账户。
6. 首阶段保留旧桥接运行。候选检测到旧桥接后只观察事件和状态，不启动候选视频或自动推送。

事件 OAuth 使用上游注册的回调地址 `http://homeassistant.local:8123`。请在能以该地址访问 HA 的同一局域网浏览器完成授权；填写的 HA 访问地址供播放使用，不会改变 OAuth 注册地址。若失败请保留现有流程并记录界面错误，不要在聊天或 Issue 发送验证码、令牌或带签名的视频地址。

## 配合测试顺序

先核对集成可加载、登录流程、设备电量和在线状态，再按一次门铃验证新事件实体。此阶段旧版三端继续工作。

视频切换必须另行安排：先暂停旧门铃自动化并停用 doorbell_local 视频桥接，确保没有旧会话正在播放，然后重新加载候选集成。不要卸载旧集成；必要时立即停用候选并恢复旧桥接和原自动化。Xiaomi Home 的其他设备不得移除。

候选选项可设置电视和小爱局域网 IP、手机通知服务。电视采用原始 H.265 EXO，小爱全屏854×480、临时80%音量并保留手动调整；手机点击通知进入 `/mi-cateye`。需要实机验证后才能认为可替代旧流程。

## 范围与回退

0.1.0rc1 已支持云端事件录像回看和下载：打开 `/mi-cateye-recordings`，选择日期、起止时间和事件类型，再选择片段播放。支持上一段/下一段；云端保留期限以米家实际提供为准。录像按需下载、服务端解密并合并，保留原始视频编码，音频封装为 AAC；不启用全天预取。缓存最多 5 段、约 128 MB、24 小时，下载到手机或电脑的文件由用户自行管理。

SD 卡回看尚未实现。当前仍为测试版；电视偶发卡顿和新旧整体内存对照尚未解决，不承诺完全离线工作。

出现问题，停用 Mi-CatEye，恢复原桥接及自动化；无需删除原凭据或重配其他设备。回退后确认只有一条猫眼视频会话。

源码来源与原始许可位于集成内 `vendor/`、`licenses/`。Xiaomi Home 的原始许可及使用限制继续适用；本项目不是官方集成，不能将整体视为 MIT。

手机前台自动弹窗可在选项填写该手机的 Browser Mod ID（需安装并注册 Browser Mod）；为空时仅发送 Companion 通知。弹窗仅定向该浏览器，保留关闭按钮和16:9画面。门铃图标状态在最后一次响铃60秒后自动复位。
